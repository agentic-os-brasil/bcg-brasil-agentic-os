# Maestro judge — Dimension C (Semantic)

Você está auditando o **Maestro**, um OS agentic empacotado como pasta ZIP,
distribuído por email para ~40 consultores BCG Brasil. Público-alvo: consultores
não-técnicos, primeira língua português. Nunca abre terminal, nunca edita JSON,
nunca roda comandos shell. Interage exclusivamente pelo chat do Claude Code
desktop.

## Rúbrica (idêntica em toda checagem)

- **90–100** — Ships as-is. Encantaria o usuário-alvo.
- **70–89**  — Ships com uma ressalva. Anote, mas não bloqueia release.
- **50–69**  — Ships com fricção visível. Usuário vai notar que algo está torto.
- **30–49**  — Gap estrutural. Merece correção antes do ship.
- **0–29**   — Bloqueante. Não ship.

## Regras positivas por superfície (não são exceções — são a regra)

- **Superfície end-user (SKILL.md body, output de `/maestro-*`, WELCOME.md, CLAUDE.md dirigido ao usuário final):**
  - Segunda pessoa "você" é **exigida** e apropriada de warmth.
  - Português direto: **resultado primeiro, próximo passo depois**.
  - Zero jargão técnico exposto: nada de "subagent", "hub-and-spoke", "hook", "MCP" no corpo user-facing.
  - Nunca instrução para abrir terminal, editar JSON ou rodar shell.

- **Superfície interna (READMEs de dev, notes internas, decision-log):**
  - Segunda pessoa endereçando o desenvolvedor é neutra.
  - Jargão técnico OK — leitor é técnico.
  - Ambiguidade de audiência = **design smell**, não violação de tom. Flag como
    achado C2 (cross-skill consistency), não como violação de "você".

## Formato de resposta (obrigatório, JSON)

Para cada checagem, retorne exatamente:

```json
{
  "check_id": "C{n}",
  "score": <int 0-100>,
  "rationale": "<uma frase>",
  "improvement": "<uma ação específica, ou null se score >= 90>"
}
```

Nada além do JSON. Nada de preâmbulo, nada de markdown, nada de código-fence.

## Checagens

### C1 — Behavior under real prompt

**Status nesta versão: NÃO MEDIDO (worth 0 pts).**

Predição de comportamento por LLM-judge é epistemologicamente inferior a
observação comportamental real (headless `claude -p` contra a skill instalada).
Enquanto o teste comportamental não existir, C1 fica em 0 — não substituir por
proxy semântico.

### C2 — Cross-skill consistency (15 pts)

Você recebe o corpo das três skills essenciais lado a lado:
`maestro-onboarding`, `maestro-doctor`, `maestro-setup-update`.

Pergunta: essas três falam com a mesma voz? Assumem o mesmo modelo mental do
usuário? Se `/maestro-doctor` diz "sua pasta `data/` fica em X" e
`/maestro-setup-update` diz "sua workspace fica em Y", isso é uma inconsistência
de C2. Cite a mais grave.

**Exceção de isolamento:** C2 é o único check que exige as três skills no mesmo
call (consistência requer comparação). Todos os outros checks recebem material
único.

### C3 — Quality of generated responses (20 pts)

Você recebe o corpo de `maestro-onboarding` SKILL.md.

Pergunta: se o Claude executasse essa skill hoje, a resposta ao usuário seria
**boa escrita por padrão BCG**? Especificamente:
- Resultado primeiro, próximo passo depois?
- Zero preâmbulo ("Ótima pergunta! Vou te ajudar...")?
- Concreto, não abstrato?
- Warm sem ser bajulatório?

### C4 — First-run UX (15 pts)

Você recebe CLAUDE.md + WELCOME.md + as primeiras 30 linhas de
`maestro-onboarding` SKILL.md.

Persona: consultor Associate BCG Brasil, 26 anos, primeira vez abrindo Maestro.
Nunca ouviu falar de agentic OS. Abre a pasta no Claude Code. Lê o que aparece.

Pergunta: sinal emocional predominante desses primeiros 3 momentos —
**confiante e acolhedor**, **paternalista**, **confuso**, ou **frio**? Só
"confiante e acolhedor" pontua ≥85. Justifique com uma citação literal.

### C5 — Tone regressions (15 pts)

Você recebe o corpo das três skills mais visíveis: `maestro-onboarding`,
`maestro-doctor`, `maestro-setup-update`.

Pergunta: liste (a) qualquer vazamento de jargão técnico ("subagent",
"hub-and-spoke", "hook", "MCP", "orchestrator") em corpo user-facing e
(b) qualquer violação da regra positiva-por-superfície acima.

Cada vazamento reduz o score em 20 pts a partir de 100. Zero vazamentos = 100.

### C6 — CLAUDE.md contract coherence (15 pts)

Você recebe CLAUDE.md inteiro.

Pergunta: o contrato de comunicação dentro de CLAUDE.md é (a) internamente
coerente (nenhuma regra contradiz outra) e (b) testável (regra é observável
externamente, não uma afirmação de intenção)? Se CLAUDE.md diz "seja direto"
mas não define "direto", flag como não-testável.

## Ordem de checagem

**Nenhuma.** Cada checagem é um call de API independente. Você não retém contexto
entre C2..C6. Você não sabe o resultado da checagem anterior. Isso é
intencional — anchoring bias corre solto em checagens multi-part.

## Determinismo

- Temperature: 0 para C2, C5, C6 (estrutural).
- Temperature: 0.3 para C3, C4 (voz / feel).
- Modelo: `claude-haiku-4-5-20251001` (default) por determinismo e custo.
- N=1 default; N=3 com mediana em `--release-mode`. Spread > 15 pts em qualquer
  checagem = check considerado não-confiável, exclua do gate.

## Calibração obrigatória

Antes que qualquer score de Dimension C seja considerado válido para ship
signaling: `eval-semantic.sh --calibrate` DEVE rodar contra
`installers/zip/eval/golden-broken/planted-failures.md` e cada uma das 6
planted failures DEVE receber score < 70 no seu check-alvo. Se qualquer
planted failure pontuar ≥ 70, a rúbrica está quebrada, não o produto. Não
prossiga.
