# Native Windows private-memory navigation

The private wiki derives navigation from one registered workspace's committed
professional memory. It uses the existing `private-memory-local-v1` profile,
keyed source references and denial generation. Authored workspace pages use the
separate `brain.*` operations; neither graph supplies authority for the other.

## Owning workflow

1. Bind the intended Maestro connector with `maestro_context`. Continue only
   when the returned workspace identity matches the requested workspace.
2. Capture only selected text through the exact reviewed `memory.capture`
   operation. Run the requested deterministic `memory.consolidate` cycle. A
   capture receipt alone is not a committed rollup or wiki generation.
3. Use the existing exact-reviewed maintenance workflow for
   `wiki-incremental-sync`, `wiki-reconcile` or `wiki-integrity-check`.
   Qualification requires genuine owning execution; a current graph or clock
   change cannot manufacture a compiler run. Recurring enrollment is separate.
4. Query `wiki.status`. A current generation permits bounded `wiki.read` and
   `wiki.source` using its exact generation and returned references. Continue
   pages with the returned cursor and retain the generation. Source or denial
   changes hide the previous whole view before rebuilding.
5. After correction or deletion, inspect the actual removal and retirement
   result. Pending retirement grants no readable last-known-good graph. Close
   conflicting applications or remove the identified local alias through an
   independently authorized operator action, then explicitly retry the owning
   operation. A query never repairs or clears a barrier.

## Windows custody

The canonical private-file owner retains the complete traversed namespace with
no DELETE sharing. Ordinary ancestors permit traversal only; the selected
workspace and graph directories still require the actual user SID and private
ACL. Reparse, nonlocal, foreign-owner and hardlinked private objects refuse.

Source snapshots and public inspection/read/compile calls retain the admitted
workspace. Staging, immutable versions and every candidate parent stay named
until complete readback and exact-parent pointer publication. The existing
activation/control/lease order, source and visibility fences, graph budgets and
strict checkpoint cohort remain effective.

Retirement retains the fixed workspace parent and DELETE-authorized recursive
children, preserving outside objects under aliases or sharing conflicts. The
source denial checkpoint remains durable when physical cleanup is incomplete.
Unix keeps its existing IO ordering and confined primitives.
