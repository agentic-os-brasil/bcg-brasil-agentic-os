# 👤 Profile — index

> Mother file (MOC) for `atlas/profile/`. Who the user is and how they work.
> Up: [Proposal 001 — Context and Brain Model](../../001-context-and-brain-model.md), §4.

## Members
- `bio.md` — life/background context beyond the role; what drives them.
- `case-history.md` — project trajectory, skills, spikes, gaps (consulting-specific; other
  personas would define an equivalent "experience history").
- `working-preferences.md` — role, working style, operational preferences. Also the landing
  place for a learning (from [`learnings/`](../learnings/_learnings.md)) once it crystallizes
  into a standing practice.

All three are **founding documents** — created once, together, during onboarding, then updated
incrementally. A robust onboarding routine that guarantees these are built with real substance
(not left as templates) is a dependency of this segment, not an afterthought.
