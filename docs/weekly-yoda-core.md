# Weekly Yoda source core and installed composition

This core is now composed by the [installed model second-brain flow](model-second-brain.md). Each installation remains **unavailable** until its own actual tuple is registered, natively qualified and separately enrolled under [Spec041](../specs/041-model-backed-maintenance-activation.md). Canonical SELF and interactive refinement retain their original authority. Ordinary session readers may consume a separately verified, bounded advisory working projection; shipping the core grants no activation or native proof.

## Complete end state and current boundary

A fully qualified weekly pass must freeze one owner-scoped input, invoke a genuinely qualified bounded adapter under its existing per-job/occurrence authority, and atomically replace a silent per-facet working projection. It must not emit a weekly user message, proposal queue or journal, and must not mutate canonical SELF. The owner product now composes explicit registration, private occurrence binding, evidence-only native qualification and separate enrollment. These source paths require whole-front review and real tuple qualification; no installed tuple is enabled by this document.

The new `WeeklyCompactionAdapter` is a typed interface only. Its presence grants no invocation authority. `BuildWeeklyCompactionInput` builds complete bounded private data without a current interactive task, flags history as quoted non-instructional data, and binds canonical, history, policy, translation and full-input digests. The existing proposal-producing Handler is deliberately not enabled as a substitute.

## Owner Context seams

`WeeklySelfOptions` is trusted controller metadata, never a public model-argument schema or authority record. Current sensitive-purpose/owner authorization must be supplied by the eventual qualified owning caller; persisted booleans are not authorization. The core does not authenticate a principal or derive execution grants.

- `FreezeWeeklySelf` accepts explicit owner-global selection, existing sensitive-facet authorization, translator identity and hard limits. It freezes exact source identities once. Retries reconstruct the same input rather than select later records.
- `ParseWeeklySelfCandidate` accepts one closed JSON object. Unknown or duplicate fields, surrounding prose, mismatched digests, unknown/missing facets and oversized text fail before publication.
- `PublishWeeklySelf` runs only through a supplied existing synchronous owning-write fence. A callback is not authority or success: the exact owning write must execute, then the current artifact is read back. Missing/no-op/late execution refuses. A failed/double boundary after a first durable commit returns a truthful partial result; the core never fabricates rollback.
- `ReadWeeklySelf` returns actual bounded working text to the explicitly policy-bound Yoda reader. It rechecks source revisions and canonical policies and performs no initialization/repair. The original service's `ReadWeeklySessionWorking` additionally requires current qualification, activation, execution and terminal evidence, and intersects independently accepted session facets before optional ordinary context consumption. Yoda-only facets remain unavailable to the session reader.
- `PruneWeeklySelf` is an explicit owned retention operation. It removes expired input/working content and invalidated views when their source snapshot can be admitted. Expired content remains purgeable when a canonical source disappeared. Reads only refuse stale/expired material; they do not purge it as a side effect.

All durable state is in one fixed private `owner/self/weekly/current.json`. The pending recovery value is a closed manifest: canonical SELF and original prompts are reconstructed from their owning stores and exact identities, not cached again. Only a non-identity normalized translation requires bounded pending text; identity normalization is reconstructed too. Deletion or correction that makes exact reconstruction impossible refuses replay. Publishing replaces current working text and clears pending content in the same atomic write. A single metadata high-watermark prevents reconstructing a pruned/expired occurrence from new evidence; there is no recurring body history.

Selected observations must be owner-global, explicit and corroborated under the canonical observation policy. Independent supporting episode revisions are also bound, so redacting the corroborating source invalidates the view. Workspace/account/case sources are not declassified or joined. New history after the frozen watermark is excluded; selected source deletion/correction and changed policy/configuration refuse publication/readback.

## Privacy and integration gates

Source mutations and their recovery paths now purge selected derived text under their existing locks before changing history, observation/support or canonical facet sources. Unrelated appends preserve immutable occurrences. Pruning runs before a normal authorized weekly freeze; probes remain memory-only. Readers immediately reject invalid/expired content, while physical expiry cleanup occurs at the next eligible owning execution.

The lock order is owner interview transition → prompt history → observation snapshot → weekly state. Observation/history mutation integrations may take the weekly lock last; they must not reacquire earlier locks. The shared observation read snapshot uses the actual integrated SelfV3 dependency. Final focused checks use this real tree without a development overlay.

No new key, credential custody or native Agent admission/proof authority is introduced. Weekly registration/qualification/enrollment reuse the existing product control and private grant. D3 remains separate and blocked. Existing experimental kit0.1.50 is unchanged. Focused synthetic tests establish construction behavior only; real model, Code/Desktop, native Windows and hosted CI remain separate gates.

The historical construction is tracked in [weekly-yoda-model-source.md](weekly-yoda-model-source.md); current source composition and acceptance boundaries are in [model-second-brain.md](model-second-brain.md). Earlier core freezes remain historical source evidence, never qualification of a current installed tuple.
