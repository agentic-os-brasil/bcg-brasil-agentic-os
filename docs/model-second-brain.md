# Installed model second brain

Maestro composes two closed model jobs through the original maintenance service.
`yoda-self-review-weekly` produces owner-local advisory working facets;
`memory-weekly` consolidates one workspace's eligible memory into canonical L2/L3
and an independently reviewable lifetime candidate. Registration, qualification,
scope and activation are separate for each job, even with the same Code runtime.
Synced product assets remain separate from the private brain in Developer.

Menu wiring is a release-integration step. The route described below is exposed
only after that source/glue is merged, built and qualified; backend helpers and
source tests alone do not add it to an existing released kit.

## First use

1. Use the installed manager's model setup. It observes the actual admitted Code
   executable, native signing/version identity, purpose profile, effective
   configuration inventory and fixed transport. Profile preparation is reviewed;
   authentication uses the official login flow for that exact profile. Credentials
   are never copied and colleagues do not author declaration JSON.
2. Select the job, provider/model and bounded policy explicitly. Yoda intersects
   independently accepted session facets with actual source sensitivity/readers.
   `ReadWeeklySelfOwnerID` preserves agreed history/weekly namespace labels and
   refuses conflicts; only an unbound label is a new human choice. This is not a
   person or enterprise identity. Memory uses its own fixed workspace policy.
3. Approve the actual server's original registration review; the job remains
   inactive and unqualified. A staged private
   proposal is not authority; Apply reobserves the tuple and uses the original
   backend, exact digest and confirmation.
4. Run separate evidence-only native qualification. Actual process creation,
   image/configuration, bounded response, terminal observation and reap must pass.
   It writes qualification evidence only, never working context or memory.
   Memory qualification first needs real eligible L1 in that same workspace;
   use the original reviewed capture and daily-consolidation flow to prepare it.
   A different rehearsal's brain or a fabricated date is not that prerequisite.
5. Enroll separately with an explicit timezone and real boundary. Normal
   foreground/serve/installed wakes discover eligible occurrences through the
   original `RunDue`. Closed-client scheduling is another explicit opt-in.

Cold startup composes the fixed executors without a declaration-file flag.
Only a stored accepted tuple, current qualification and original live
job/control/lease grant authorize a call. Refused declarations change no options.
The transport is one bounded tool-free authenticated Code process, with the
original supervisor, cancellation, native session and strict vendor envelope.
Each job has a distinct fixed prompt, source policy, response validator and
publisher. There is no generic command runner or API-key fallback.

## Memory publication and later lifetime review

The model receives frozen eligible L1 for one week and exact prior active
L3/lifetime sources. It returns only scope/input bindings and `L2`, `L3`,
`lifetime` text. The original memory engine owns provenance, budgets, eligibility,
visibility and its atomic commit. Missing lifetime review retains useful L2/L3.

A bounded private `model-weekly.json` sidecar is staged in that same version.
The original committed L3 filename includes SHA256 of its exact bytes. The reader
validates the confined canonical pointer/anchor, closed record and exact current
L2/L3, source, policy and candidate digests. The sidecar is not native authority:
current registration, qualification, execution/control and receipts remain required.
The original manifest and Artifact JSON schemas remain unchanged; old strict
readers round-trip them and consume canonical artifacts while ignoring the sidecar.

Explicit `memory.consolidate` for the same period reuses a still-current exact
candidate and original foreground review, without another model call. Promotion
republishes byte-identical L2/L3 with lifetime and the updated anchored sidecar;
it creates no new L3 content digest or continuity evidence. Decline retains the
pending candidate. Changed source cohorts cannot promote old text; an explicit
current deterministic consolidation reports the prior pending source change.
Correction/deletion synchronously deny old visibility and physically purge private
sidecars with generated versions. Cleanup failure remains unavailable and visible.

Producer-specific cache/reprocessing remains intact. Lifetime eligibility also
requires distinct eligible L1 cohorts through exact canonical L3-to-L2 edges;
changing a weekly provider or format cannot manufacture continuity. Scheduled
`memory-deep-dream` and `memory-weekly` enrollment/resume are mutually exclusive:
the owner explicitly pauses the former engine before selecting the other.
Authentication/model failure never silently falls back to another engine.

The committed execution/output identity supports original lease-fenced terminal
metadata recovery without replaying the model. A model response, staged version
or missing terminal receipt never means a complete occurrence.

## Ordinary consumption and evidence

Canonical memory context reads actual validated L2/L3 through its original path.
Optional Yoda working context is advisory, at most 4096 bytes, independently
intersected with accepted session facets. Current source, expiry, registration,
qualification, activation, execution and terminal checks must pass. It cannot
replace canonical SELF, disclose Yoda-only facets or authorize tools or effects.

| Outcome | Required evidence |
| --- | --- |
| Source construction | Closed parser, source/privacy, atomic storage, old-reader and SDK checks |
| Registered | Actual observed tuple and accepted original review |
| Natively qualified | Genuine supervised process/response/reap for this exact job/tuple |
| Enrolled | Separate reviewed schedule, scope and activation boundary |
| Model effect | Real due occurrence and validated atomic domain readback |
| Complete occurrence | Original terminal and scheduler receipts, or truthful reconciliation |
| Closed-client wake | Actual platform definition, opt-in, eligibility and observed runtime |

Synthetic tests and cross-compilation prove source behavior, not model, native
client/platform, calendar, signing or delivery acceptance. The owning contracts
are [Spec041](../specs/041-model-backed-maintenance-activation.md),
[Spec006](../specs/006-memory-persistence.md) and
[Spec062](../specs/062-product-maintenance-service.md).
