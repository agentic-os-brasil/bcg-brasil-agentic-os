# Experimental Windows runtime preparation

The Windows engineering carrier contains the signed Maestro server, base bundle and whole-release metadata. It contains no CPython archive, wheel, third-party DLL or assembled runtime archive. A separately signed public acquisition recipe sits outside that incomplete release directory. The existing `VerifyDirectory` contract continues to require every artifact.

`internal/ingest/docling/acquisition.Review` authenticates the pinned authority, whole manifest and same-key canonical recipe, verifies the exact selected server and non-runtime carrier, and returns public input identities and existing reusable cache state. Review performs no downloads, runtime execution, writes or permission repair. The native caller must show the exact initial download size, upstream publishers, cache/destination, expiry and assembly effects and obtain conscious confirmation before calling `Acquire` with that exact plan.

`Acquire` revalidates the signed inputs and review, accepts Windows amd64 only, and preserves an owner-private cache. Complete verified blobs can resume after a fresh review; partial files are never interpreted as complete or used with HTTP Range. Each explicit attempt uses a new private directory. The review discloses retained bytes and a conservative maximum additional allocation; retained plus additional bytes cannot exceed 2 GiB. Three attempt directories bound retained interrupted work; exceeding that limit refuses without cleanup or overwrite. A caller must select a new private cache after reviewing that additional storage effect. No automatic retry or fallback package resolver exists.

Only the compiled profile's exact interpreter and package URLs may be requested. HTTPS uses normal certificate validation, no ambient proxy, credentials, cookies or sensitive headers, a bounded publisher-specific redirect chain, and an explicitly vetted public DNS address for the actual socket. Errors omit upstream URLs, response bodies and signed redirect query strings. Every file has exact expected size and SHA-256 before reuse or assembly. All assembly outputs stay in the attempt directory; a new complete release snapshot receives only authenticated signed release files and the exact assembled archive. Ordinary whole-release verification precedes the returned `VerifiedRelease`.

No downloaded interpreter or package runs during acquisition/assembly. Installation, native AppContainer qualification and actual conversions remain with the existing separately reviewed runtime path. Cross-compilation and local transport fixtures do not attest real Windows acquisition, DLL loading, conversion, kernel confinement or client integration. Direct upstream acquisition avoids transferring runtime bytes in this carrier; missing applicable redistribution grants remain an unresolved external question and this route is not legal clearance.
