# Maintenance while the clients are closed

Use the original participant launcher and choose **maintenance** in the local manager. This console uses the same admitted installation, owner, Developer brain, workspace, carrier and source as the ordinary MCP clients.

## Prepare work

1. Choose **status** and inspect actual jobs and their current reasons. Register any required model transport through its separate reviewed setup; a provider login does not qualify a job.
2. Choose **qualify** for one eligible job, read its full original review and confirm. A qualification runs the actual owning handler and needs genuine inputs.
3. Choose **enroll** for that qualified job, select its timezone and confirm its original review. Enrollment defines the real future boundary; the wake does not invent earlier work.
4. Choose **wake-opt-in**, read the complete OS definition, binding and effects, then confirm. Choose **wake-status** to inspect actual owned native registration.

The native pulse discovers due work every fifteen minutes. On macOS the original LaunchAgent also wakes at load. Windows uses the current logged-in user's interactive token and least privilege, on AC power; native Task Scheduler/enterprise policy may refuse enrollment. No password, WSL or administrator setup is implied.

## Pause or remove

**wake-pause** stops native discovery and closes its eligibility; **wake-opt-in** can resume the same reviewed owned definition. **wake-revoke** removes only that exact owned native task. These controls preserve every job's qualification, grant and data. A client that remains open can still run enrolled jobs through its existing serve worker. Pause or revoke the named job separately to withdraw that job's authority across every caller.

Unknown or changed native definitions are preserved for diagnosis. A partial/timeout OS acknowledgement remains unknown; the manager does not silently reenroll another task. The finite experimental role and current source remain required, including for management; expiry requires the existing admitted recovery path.

On macOS, review reads the exact private definition without requiring launchd
to respond. Applying an action closes its Disabled barrier before native access.
Opt-in keeps that barrier closed through full command/argument and enabled-state
readback, then rechecks the current installation and opens the file last inside
the same bounded transaction. Unknown, timed-out or cancelled acknowledgement
leaves the file disabled, including when pause/revoke cannot reach launchd. The
legacy shared LaunchAgent keeps its existing lifecycle.

## What status proves

A loaded/registered native task proves its observed OS configuration only. A manual invocation cannot establish native scheduling. A real wake reporting **no_due_work** is distinct from an actual eligible domain commit, its immutable result/readback and any actual model invocation. A qualification or wake pulse never promotes lifetime memory or changes another job's scope.

With both clients closed, qualify native delivery using the exact owned OS task's actual execution observations and original domain receipts. Read committed results through the ordinary next-session readers. Do not change the clock, fabricate past occurrences, hand-edit private records or import old proof.

The same stable installer and source locator survive a permitted source update. Every wake reauthenticates the current carrier, source, role and server image; executable/configuration-bound job qualification may require a new explicit review. It never activates a release or repairs a stale client packet.

## Engineering and native evidence

The adapter construction and focused/cross-compiled tests are engineering evidence. Actual Mac and actual Windows task enrollment/delivery, closed-client eligible execution, idle/activity cancellation, revocation and final next-session readback remain separately recorded acceptance. No source-only check qualifies a client or production distribution.

Windows implementation follows [TaskFolder.RegisterTaskDefinition](https://learn.microsoft.com/en-us/windows/win32/taskschd/taskfolder-registertaskdefinition), [Task Scheduler security contexts](https://learn.microsoft.com/en-us/windows/win32/taskschd/security-contexts-for-running-tasks), and the [registered task object](https://learn.microsoft.com/en-us/windows/win32/taskschd/registeredtask). It uses TASK_CREATE and TASK_LOGON_INTERACTIVE_TOKEN, validates the fixed current-user principal and complete command before changing an existing task, and leaves unrelated tasks untouched.


Windows eligibility also requires the installer's private native-definition
control, independent of Task Scheduler's enabled flag. The reviewed revision
advances before every opt-in, pause or revoke, including when no task is present.
A timed-out or delayed COM enable cannot reopen that control. Opt-in opens it
only after exact successful readback and a current live transaction; pause/revoke
retains the disabled record before touching the task. Missing or unsafe control
refuses a worker; an explicitly reviewed first action may bootstrap a disabled
record. This is OS wake eligibility only, with job grants and actual execution
proof kept separate. Do not delete or manually repair the control to retry.
