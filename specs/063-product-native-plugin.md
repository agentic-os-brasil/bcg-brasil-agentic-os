# Spec 063 - Product native plugin surface

Status: construction contract; configured packets, compiled adapter execution,
native host qualification and release readiness remain separate evidence.

## Outcome and authority

The admitted participant can use the shared MCP product in Code or Desktop and,
on a supported qualified Code host, load the canonical native specialists and
their bound lifecycle/guard adapter. Reuse the existing MCP executable; no new
daemon, network service, legacy CLI resurrection or automatic Python install.
An MCPB carries the shared server/resources, not native Code agents or hooks.

Spec057 owns execution, Spec060 owner/memory, Spec062 maintenance and Spec020
release trust. The active native graph is bounded sequential maestro_planner.
Native_advisory is a different profile and remains unavailable until separately
implemented and qualified. Native events cannot grant extra delegation depth,
filesystem authority, completion or review custody.

## Explicit non-enforcing lifecycle context

Decision PHLC adds an explicitly selected `mcp_lifecycle` Code packet mode.
It carries the ordinary MCP server and methods plus exactly SessionStart,
UserPromptSubmit and Stop command hooks. Its separate lifecycle capability
reports configured delivery, native execution not observed and enforcement
unavailable. It projects no native specialists, pre-tool guard or approval and
completion authority. Plain `mcp_only` packets still contain no hooks; the full
`maestro_planner` profile retains its original exact-host qualification gate.
The modes are mutually exclusive. MCPB remains the shared server/resources
carrier without Code hooks or a claim of Desktop Skills installation.

These hooks bind exact participant-local selections in the existing canonical
packet inventory. MCP and hooks use the same fixed selections; the local profile
removes userConfig rather than interpolating untrusted path bytes into a shell.
Generic distributed packets remain path-free. For stable clients the existing
reviewed request owns explicit lifecycle_context opt-in, probes the actual
installer/current server protocol and materializes the same canonical profile.
Its finite stable-hook owner accepts exactly the three passive events and reuses
stable-launch source/client/workspace/current-input guards before selecting the
current executable. Non-opted-in and stale clients refuse; no direct pinned-server
fallback can bypass that owner. Desktop and plain default profiles remain unchanged.

These hooks call the same admitted executable with explicit bound product,
owner and workspace paths. Preserve normal host permissions, source/process
validation, bounded event input and private-body-free diagnostics. Use only
documented command-hook configuration. A configured passive command does not
claim fail-closed enforcement on an unsupported or unobserved host.

SessionStart reads the existing admitted workspace and eligible generated
memory through the visibility-checked reader shared with `memory.context`.
Preserve canonical layer order, per-layer budgets, an independent 8-KiB memory
ceiling and the 16-KiB total context ceiling. Frame memory as historical data,
never instruction or authorization. Empty, invalid, corrected, deleted or
changed views produce bounded omission diagnostics rather than raw-history
fallback. The full native adapter may reuse this same read-only projection.
UserPromptSubmit emits metadata only and does not enter native agent-flow
admission. Stop respects recursion and records only a confined typed lifecycle
observation; it cannot invoke the enforcing unresolved-route Stop path.

Filesystem creation belongs to explicit setup through the existing datahome,
workspace, owner and memory initialization owners. Repeat preparation preserves
existing content and keys. Startup, prompt and stop never initialize or repair
missing state, capture transcripts, run a worker, compile a wiki, dream, enroll
jobs or change an execution checkpoint. Authored workspace `brain/`, private
owner memory and binding/execution metadata retain their separate roots.

Acceptance separates generated configuration and real compiled-command tests
from a real client's context delivery and Stop observation. Record the actual
host version, selected plugin/binding and private synthetic receipts. Passive
client delivery is not full native qualification, Windows device acceptance,
automatic second-brain maintenance or production release approval.

## Canonical identities and projection

Maestro remains the main-session hub. Project the six canonical specialists:
case-agent, client-account-agent, darwin, gamma-guardian, pa-expert and yoda.
Reuse embedded definitions/catalog/templates and one pure projection shared
with the existing workspace renderer. Frontmatter must be first; preserve
ownership recognition and conflict-safe replacement of older managed files.

Keep tool-free account, Darwin, PA and Yoda profiles and the existing Case Agent
file-tool contract. Gamma initially performs tool-free bounded packet analysis;
its source-head inspection/grant and longitudinal custody remain unavailable.
This projection does not qualify all of Spec043. User-specific identities,
private profiles and workspace data never enter compiled product assets.

Plugin invocations use exact maestro-product:<canonical-id> identifiers. Rewrite
executable Agent references only; preserve canonical IDs, paths, policy and
provenance. Normalize only the exact admitted namespace. Unknown own-namespace
IDs and spoofed prefixes cannot become managed specialists. Tools do not gain
authority from a prompt, a metadata file or successful name resolution.

## Bound hook adapter

The existing MCP executable exposes a narrow hook command with an event and
the existing admitted product/home/workspace binding. Validate that binding on
each invocation; cwd, ClientInfo and model flags are not binding authority.
Reuse canonical claudeadapter, claudeagents, sessionhook, lifecycle and
nativeagentflow rather than translating Claude through the ZIP Codex adapter.

SessionStart is wholly read-only and bounded; approved generated memory follows
the PHLC projection above without acquiring instruction authority. UserPromptSubmit
may update admitted flow metadata but never stores prompt/transcript text or
silently captures memory. Validate event-specific required fields against the
actual host protocol and bound raw input. Discard private bodies from receipts,
diagnostics and errors; no transcript-file traversal is needed.

PreToolUse covers all tools. Validate dispatch before Agent/Task creation and
correlate subsequent native agent IDs with the admitted target and session.
SubagentStart cannot prevent creation; an invalid transition must not authorize
the child's later tools. Enforce current graph, specialist policy and canonical
workspace/cross-case guards. Close Glob-pattern escapes in the reused guard;
content-search regexes are not filesystem paths. Preserve native permission
prompts. Pre-tool path checks establish policy admission, not filesystem race
confinement or a replacement for platform permissions.

PostToolUse/SubagentStop/Stop record bounded transitions with retry safety and
existing confined flow storage. Respect stop_hook_active. Agent stop is not
evidence of delivered artifacts, a Yoda verdict or execution completion. Do not
publish fake custody or mutate the execution ledger on this observation alone.
Dreaming, indexing and EOD actions remain explicit or separately enrolled
services; removed ZIP first-run behavior must not reappear as auto-init.

SubagentStart has no dispatch tool-use ID. Correlate only the sole pre-admitted
pending canonical target in the same workspace/session; mismatch or ambiguity
grants no later tool authority. Host ordering is a qualification requirement,
not an identifier invented by the adapter.

Use a real prompt_id when present. It is not universally mandatory, and neither
prompt text nor its hash may substitute for an occurrence identifier. Without
an unambiguous new occurrence, preserve conservative/idempotent flow state and
report turn_reset_unavailable instead of resetting a prior flow. Ordinary MCP
use remains available. Source/API fixtures cannot establish actual host fields.

Keep the existing bounded flow store under admitted owner state. Hold its
private lock across read/validate/mutate/atomic publication, with internal
revision checks, native-ID correlation and bounded replay identities. Reject
unsafe store aliases and overflow rather than discarding a replay fence.
Rename completion-like observation fields; old metadata never grants verified
completion. Reuse held-directory private publication, not the explicitly
nonatomic replacement helper or a second transaction service.

Product context uses a narrow owning directive projection to actual MCP
operations; shared legacy text must not emit removed commands or acquire
effects. Extract callable deterministic workspace policy from the ZIP adapter,
without invoking its codex-hook. Guard filesystem-bearing glob/path fields and
known prefixes/targets; Grep text regex remains text. Unsupported ambiguous
patterns fail policy admission. Event-aware diagnostics remain private-body-free;
failure on a nonblocking event is not prevention, and Stop/SubagentStop cannot
inherit an onFailure:block guarantee that the host does not provide.

## Host admission and failure behavior

Native packet generation requires an opaque admitted NativeHost produced by a
real participant-local qualification path, binding the actual Code
executable/version, platform, adapter profile and corresponding evidence.
The existing executable implements native-review followed by the explicitly
confirmed native-qualify-and-build command. Qualification mints process-local
admission and immediately consumes it to build the selected packet. It does
not install the packet or register a connector. Serialized booleans,
caller-supplied version strings, ClientInfo and test fixtures cannot establish
production native qualification. Engineering fixtures remain labelled as such.

Review binds the selected installed native executable, actual target workspace,
supported local settings/instruction closure, server and adapter profile. It runs bounded
version and auth-status subprocesses, with no model call or product-owned
scratch/challenge/packet write or registration change. This does not attest to
arbitrary diagnostics written by the operator-selected installed CLI. Apply requires the
same reviewed digest and explicit confirmation, revalidates those bindings and
uses the actual workspace as its working directory. A sibling synthetic target,
alternate login profile or serialized evidence cannot qualify another target.
The selected scratch root must already be private and owner-checked, lie beneath
the admitted user home, and be disjoint from product, workspace and canonical
state. The new exact challenge directory belongs beneath the admitted target
workspace. The public selected server must lie outside that workspace for the
nondestructive negative Read control. The owner must review
which workspace context may be loaded and sent to the native provider, along
with the canonical private flow/receipt writes made by the real hooks.

The supported local closure includes local instruction alternatives, bounded
recursive rule membership, transitive imports and relevant named startup-mode
controls. Missing-file membership and new applicable files participate in the
binding. Preserve the selected configuration root's compatibility aliases;
unsupported source aliases, ambiguous roots/imports or closure overflow refuse
before effects. Settings must already explicitly disable auto-memory in the
supported local profile. Additional-directory/third-party-plugin sources,
unsupported managed-settings directories and ambiguous Git/worktree settings
layouts remain unavailable; qualification never changes the owner's settings
to make a profile eligible.

Remote or OS-delivered managed policy is not exposed completely by this host
protocol. The full review includes an explicit digest-bound UNATTESTED fact and
context/startup disclosure. Known local managed inputs still require binding or
refusal. Do not invent an absence signal, treat confirmation as policy evidence,
or equate local autoMemoryEnabled:false with a complete managed-policy claim.
Native observation qualifies the supported local closure and actual observed
guard/failure behavior only. Enterprise device-policy admission remains a
separate external gate; no local observation or fixture creates production
rollout authority.

Inspect host identity with a bounded held-file streaming path independent from
the selected server payload reader. The local host limit is 512 MiB; preserve
the server's 128-MiB payload limit. A genuinely supported minimum-version binary
must not be rejected merely because it exceeds the smaller server limit.

The attended command bounds execution to three CLI sessions, each with at most
eight parent turns and 120 seconds. A positive max-budget-usd no greater than one is
required for each session; provider-reported billing is an estimate, and child
delegation can issue additional provider requests. This is not a hard spending
ceiling. An observed excess stops subsequent sessions. Cancellation addresses
the owned process group; detached descendants remain unattested. No global
process cleanup, flow-fence reset, permission bypass or unattended activation
is authorized by qualification.

Positive evidence must come from the actual host: a synthetic allowed Read,
nondestructive out-of-scope Read denial, canonical Case-to-Gamma sequence, and
separate missing/failing/timed-out helper sessions. Candidate-only instrumentation
must retain the canonical decision and nonce, require a native hook failure
envelope plus host-generated blocking tool result, and prevent unrelated or
background effects. Assistant prose, sentinel absence and helper stderr do not
prove host enforcement. Startup state is unchanged. Marker-free qualified
packets and explicitly labelled engineering fixtures remain distinguishable.

The supported enforcement profile requires Code >=2.1.295, direct exec-form
hooks and onFailure:block on enforcement commands. These are documented in the
[official hook contract](https://code.claude.com/docs/en/hooks#block-the-action-when-a-hook-fails)
and [command fields](https://code.claude.com/docs/en/hooks#command-hook-fields).
The admission path must withhold native activation when the host/profile is
unknown, unsupported, stale or unqualified. It must emit a functional MCP-only
packet with an explicit native capability reason and no active native hooks.
The six canonical specialist projections remain inert instructions as required
by the portable agent contract. Their presence never establishes native admission.
Do not invent a plugin-manifest compatibility field or a native client identity.
Windows native admission is currently refused; compiled/source tests do not
change that capability state.

The existing `packet-inventory.json` remains the canonical closed file inventory;
`maestro-packet.json` adds canonical resource hashes, references and diagnostic
native capability labels. Both carriers retain the shared portable managed
payload and external runtime selections. Final native hook vectors use the
same relocation and selection tokens plus an optional SHA-256 selection equality
check on the existing hook command. That check binds owner/workspace identity,
allows managed relocation, refuses changed selections before hook effects and
never creates qualification authority. Candidate-only instrumentation with exact
synthetic paths stays in the participant's private scratch directory.

Hook denial, malformed input and failures use actual event-aware exit/output
semantics. Native missing/crashing/timed-out helper behavior requires exact-host
qualification; an in-process callback or compiled command test is insufficient.
CLI and Code tab evidence remain distinct. Source construction must provide the
real admission/qualification entrypoint, even when auth/device policy prevents
running its attended native proof in this environment.

## Packet closure and acceptance

Explicitly allowlist the selected target server, public pinned registry,
manifests, entry skills, all admitted method files, canonical agent assets,
policy/provenance/licenses, native projections and hooks where admitted. Record
exact OS/architecture, original/projected hashes and executable modes. Use only
supported host manifest fields. Additional referenced assets must be enumerated;
replace supported obsolete commands with admitted operations and report genuine
missing execution as unavailable. No inert helper counts as functional parity.

Both carriers include maestro-packet.json with the exact target platform,
architecture, file modes and hashes, selected server, all method and agent
resources, and policy/license/provenance inventory. Referenced assets are typed
as embedded, external source or individually unavailable. MCPB carries the same
server and immutable resources, without active Code agents/hooks or a claim of
Desktop skill installation. Plain packaging runs no native probe and preserves
the explicit MCP-only fallback when actual host admission is absent.

SDK and rebuilt stdio read every immutable resource and reject private/traversal
references. Independent packet oracles cover six specialists, all seven canonical
identities, namespace references, hook argument vectors, target/modes, no native
activation without host admission and a complete transitive closure. Execute the
real packaged hook binary against allowed/denied, malformed, stale, cross-scope,
spoofed-ID, retry and read-only-startup fixtures; verify no prompt persistence.
These prove source/adapter behavior only. Organization signing, Windows private
handle/non-elevation qualification, native failure behavior, actual delegation
delivery and attended Desktop/pilot acceptance remain explicit external gates.
