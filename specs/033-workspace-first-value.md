# Spec 033 - Workspace first-value vertical

Status: accepted; conversational first-value behavior follows FREE. The governed
MCP first-case profile is tracked in #545; native-client qualification is separate.

## Objective

Deliver the first useful professional result from a workspace through a guided
conversation, while the canonical local owners retain the governed state.
Compatibility CLI commands are not the new participant workflow.

## Contract

The reviewed brief contains mandate, decision, horizon, objectives,
stakeholders, authorized materials, constraints, success signals, open
questions and balanced bullish/bearish hypotheses. Every thesis contains its
evidence, assumptions, counter-evidence and invalidation signal.

The plan has one to three actions. Each names an outcome, accountable owner,
next step and observable completion criterion. The complete first brief and plan
are one canonical authored Markdown page at the admitted setup destination,
with current frontmatter, classification and provenance. New client cases use
`brain/accounts/<account-id>/cases/<workspace-id>/<workspace-id>.md`; direct
internal cases use `brain/projects/<workspace-id>.md` without an account.
Existing exact case IDs/destinations win. Additional deliverables, decisions,
tasks or account narrative are not automatic side effects.

Private metadata and the legacy deterministic first-value CLI remain
compatibility/recovery surfaces. The MCP bridge does not expose arbitrary
first-value deliverables paths or the old multi-write helper. A new conversation
never requires owner-supplied run IDs, JSON envelopes or `value submit`.

## Conversation and completion

The managed guide asks the six minimum questions: decision and horizon;
audience/constraints; useful result; authorized material; balanced hypotheses;
and next owner/step. The agent shows the normalized brief and one-to-three
action plan and offers an explicit brain Save through the native reviewed
publication owner. Registration is prepared through the exact reviewed case
setup owner; data-free scope/control metadata stays separate from the full
human-authored brief. Read back the saved page and actual revision before
reviewed finish. A correction uses current brain CAS, not overwrite by path.

Create a ledger checkpoint only when the owner requests/accepts that work. The
setup finish owner derives one stable setup identity, atomically creates or
recovers the existing item, and reconciles revision/attempt-fenced
start/checkpoint/pause. It rejects changed accepted work/artifacts and survives
interruption before linking that item to setup. No title search, duplicate
create or second task store is used. Without requested work, finish does not
require or create a checkpoint.

A later conversation inspects the same setup and source, preserves their IDs
and continues at current revisions rather than replaying the interview. Report
completed/pending effects, including `active_cleanup_pending` after client
selection committed but exact pending cleanup remains. Reuse the same reviewed
finish only while its authoritative snapshots still match; never reset markers
or restore a previous active case to simulate rollback. Native review absence
leaves persistence pending rather than selecting a raw-file/CLI bypass.

## Metrics and limits

`time_to_first_value_seconds` begins when the deterministic run starts and ends
when the artifact is available. `manual_interventions` counts only explicit
brief, plan or artifact correction kinds. Both remain workspace-local and are
not performance measures.
These names describe retained compatibility measurements; the MCP first-case
route does not fabricate them from conversation or claim they were emitted when
its actual result contains only setup/page/work state.

No document ingestion, wiki, dreaming, external research execution, economic
refresh or new agent role belongs to this vertical. Canonical local registration
does not activate a runtime, grant tools, dispatch specialists or establish
publisher/platform signing. A kickoff packet remains pure until a separate
explicit Save/work request. Broader account narrative and all other parent
methods are not declared delivered by this first-case unit.
