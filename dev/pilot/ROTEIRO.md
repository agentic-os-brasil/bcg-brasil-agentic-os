# Teste guiado do Maestro MCP

Use somente dados sintéticos. Para conferir cada cliente de forma independente e somente leitura, escolha **3 — Conferir conexão Code** ou **4 — Conferir conexão Desktop**. Para o ensaio completo de continuidade, escolha **1 — Ensaio completo no Code** e depois **2 — Retomar no Desktop** e **6 — Conferir persistência no Code**: o Code recebe os textos automaticamente e o Desktop exige uma única colagem. Workspace, trabalho, página e marcadores são preenchidos pelo ensaio.

Para conferir apenas a conexão no Code, abra **Testar Maestro** e escolha **3 — Conferir conexão Code (somente leitura)**. O Code abre com o texto exato da conferência como prompt inicial, sem copiar ou colar. O perfil separado pode pedir login: conclua o fluxo normal nessa janela. A resposta deve mostrar o workspace esperado e o estado `ready`, obtidos por uma única leitura do MCP declarado pelo plugin. O estado `ready` descreve a saúde da conexão, não o estado dos trabalhos. Você pode repetir essa consulta preservando trabalhos, páginas, onboarding e memória. Se o login, o plugin ou a leitura falhar, envie a mensagem real; abrir o cliente ou ter login em outro perfil não comprova esta conexão.

Para qualificar os **sete hooks nativos do Code**, há um caminho opcional separado:

1. Conclua o login e a conferência da opção **3** acima. Feche essa conversa antiga do Code e volte ao menu **Testar Maestro**.
2. Escolha **5 — Qualificar os sete hooks do Code**. Essa ação usa modelo e pode gerar cobrança. A estimativa por sessão é uma escolha sua exigida para registrar o plano, não uma cotação de preço nem um teto garantido de cobrança; o menu explica os limites e mostra a soma estimada no plano completo.
3. Leia **todo o plano retornado**. Digite `QUALIFICAR` somente se concordar com esses testes. Vazio ou outra resposta cancela. Se a revisão ou a qualificação recusar, preserve o resultado e a mensagem; não apague nem repita automaticamente.
4. Após sucesso, reabra **Testar Maestro → 1** para o exercício com o pacote qualificado, ou **Abrir Code** para uma conversa vazia. O launcher seleciona o pacote e as pastas automaticamente. Use uma conversa nova; a antiga não ganha hooks retroativamente.

O ensaio **1 → 2** abaixo verifica criação, pausa e retomada do trabalho entre clientes; ele não qualifica os hooks. Preparar, abrir Code normalmente e conferir conexão não executam a opção 5. No Desktop, o teste continua sendo da extensão MCP e seus recursos, sem hooks ou agentes nativos do Code.

No Windows, o início automático e a qualificação da opção 5 exigem o executável nativo `claude.exe` no PATH. Se a mensagem indicar somente um shim, disponibilize a instalação nativa pelo fluxo autorizado ou abra **Abrir Code.cmd** sem argumentos e cole o `CODE-CONEXAO.txt` do diagnóstico atual. Para o ensaio completo, a alternativa manual usa `CODE.txt`; ela não executa a qualificação. O kit preserva a instalação existente.

Para conferir apenas a conexão no Desktop, escolha **4 — Conferir conexão Desktop (somente leitura)**. Confirme a instalação da extensão **Maestro MCP — Ensaio …** indicada. Antes de colar, abra **Configurações → Extensões → a extensão deste ensaio** e, somente na linha **Maestro context** (`maestro_context`), selecione **✓ / Sempre permitir**. Preserve as demais permissões. ✓ / Sempre permitir libera só a leitura; gravações de conteúdo exigem revisão exata no formulário nativo ou no navegador local selecionado neste ensaio. Abra uma conversa nova e cole uma vez o texto copiado. Ele faz uma única leitura de contexto e mostra o workspace esperado e a saúde da conexão, sem consultar ou retomar trabalhos. O Desktop não exige o comando Code nem um trabalho criado no Code para essa conferência. Os pacotes já usam as pastas aprovadas; não há diretórios para copiar. Preserve outras extensões e pare se o cliente propuser substituir uma de outro ensaio.

**Revisão do dono:** O Desktop deste ensaio e o Code do kit completo selecionam explicitamente a revisão local no navegador para gravações protegidas. Uma solicitação interativa abre o registro completo no navegador deste computador, mesmo quando o cliente oferece formulário nativo. Leia o conteúdo, marque a caixa inicialmente desmarcada e escolha Aprovar alteração exata ou Recusar. Fechar a aba, cancelar ou ultrapassar 150 segundos não aprova. Este canal local não qualifica formulários MCP, hooks ou bloqueio nativo. Se receber `confirmation_unavailable`, deixe a ação pendente, preserve a mensagem e envie o RELATORIO.md ao time. Não repita a chamada, não contorne o bloqueio nem use um sim no chat como aprovação. A permissão de leitura não aprova gravações.

1. Abra **Testar Maestro** na pasta `launchers` do ensaio. O verificador testa a conexão MCP do pacote, confere os recursos e abre `RELATORIO.md`. Nenhuma chamada ao modelo é feita nessa etapa.
2. Se o relatório estiver bloqueado, envie esse Markdown ao time e pare. Preserve a pasta; o relatório distingue preparação, pacote e conexão. Se o comando `claude` estiver ausente, disponibilize o Code pelo fluxo normal antes de escolhê-lo; isso não comprova ausência do Desktop.
3. Escolha **1 — Ensaio completo no Code**. O perfil isolado abre com o texto exato do ensaio como prompt inicial, sem copiar ou colar. Faça login normalmente se solicitado. Ele verifica o ID, conduz o onboarding sintético e consulta três métodos canônicos pelo MCP. Essa consulta não comprova invocação de Skill nativa pelo cliente. O resultado do método de modelagem — três entidades, definições e relações — é salvo integralmente numa página sintética e lido de volta. O mesmo texto conduz dois controles de memória: leia e aprove o primeiro registro fictício; leia e escolha **Recusar** no segundo. Fechar ou deixar expirar não testa a recusa explícita. Se o segundo for aprovado sem querer, preserve o registro e reporte a falha, sem apagar para obter sucesso. Uma captura aceita já existente e idêntica é reutilizada; as gravações não são repetidas e a decisão anterior não é inferida da ausência. Depois o ensaio cria e pausa um trabalho. Cada gravação segue a revisão humana normal apresentada pelo produto.
4. Abra **Testar Maestro** novamente e escolha **2 — Retomar no Desktop**. Confirme a instalação da extensão **Maestro MCP — Ensaio …** indicada no relatório; ela já usa as pastas preparadas, sem campos de caminho para salvar. Preserve outras extensões Maestro e pare se o cliente propuser substituir outra extensão. Antes de colar, abra **Configurações → Extensões → a extensão deste ensaio** e, somente na linha **Maestro context** (`maestro_context`), selecione **✓ / Sempre permitir**. Preserve as demais permissões. ✓ / Sempre permitir libera só a leitura; gravações de conteúdo exigem revisão exata no formulário nativo ou no navegador local selecionado neste ensaio. Abra uma conversa nova e cole o texto já copiado: ele precisa responder pelo mesmo workspace, localizar exatamente um trabalho do ensaio, reler o modelo completo salvo e a memória aceita, verificar a ausência do registro recusado e só retomar se estiver pausado. Se a extensão estiver desativada ou não aparecer, confira **Configurações → Extensões → Configurar → Ativado** nessa extensão. A chave ativada, sozinha, não confirma a conexão. Não precisa copiar IDs ou revisões.
5. Volte a **Testar Maestro → 6 — Conferir persistência no Code (somente leitura)**. O Code recebe o texto automaticamente: ele relê o mesmo trabalho, modelo salvo e memória aceita, confere a ausência do controle recusado e compara o estado e a revisão do trabalho antes e depois, sem retomar ou gravar nada. Para ensaiar um reinício frio, feche antes somente as sessões Code e conexões Desktop deste ensaio pelo fluxo normal e depois escolha 6; preserve outros trabalhos. Registre se esse fechamento foi realizado. Abrir uma conversa nova não comprova reinício do processo MCP, e a releitura não atesta sozinha o reinício.

Se o kit contém **RUNTIME.json**, os textos completos das opções **1** e **2** incluem a conversão do arquivo sintético **maestro-pilot.docx**. Siga o texto já aberto ou copiado pelo menu: confira a disponibilidade do conversor, converta somente esse arquivo e leia o artefato retornado, verificando o marcador e a tabela. O relatório registra versão, alvo, validade e identidade do runtime. A conferência automática só verifica disponibilidade; anote separadamente se a conversão e a leitura ocorreram em cada cliente. Preserve o documento de origem. Se o runtime estiver expirado, indisponível ou divergente, pare essa parte e envie a mensagem; não instale componentes nem use outro conversor para completar o ensaio.

A memória é verificada como captura L0 pelas leituras próprias de memória. Sua presença não comprova injeção passiva, rollups, digests, dreaming, agendamento ou execução dos agentes; esses recursos exigem suas qualificações separadas. Ausência do registro recusado também não comprova, sozinha, que a decisão humana de recusar ocorreu.

O relatório automático mantém **Code, Desktop, login, confirmações e hooks como não testados**. A conexão feita pelo verificador não atesta que o cliente carregou o plugin. Anote o que você observou nesses clientes.

Para devolver o teste, envie somente o `RELATORIO.md` mais recente, com este complemento curto:

- Versões Code/Desktop e sistema/arquitetura.
- Code: abriu / MCP respondeu / skill funcionou / não testado.
- Desktop: importou / MCP respondeu / retomou o mesmo trabalho / não testado.
- Página com modelo completo, memória e trabalho na opção 6: passou / falhou / não testado; reinício frio informado / não realizado / não atestado.
- Qualificação opcional (menu 5): não executada / cancelada / qualificada / indisponível; registre separadamente da continuidade do trabalho.
- Memória aceita e recusada, hooks e mensagem de erro: resultado real.

Confira o Markdown antes de compartilhar. Preserve `owner`, `workspace`, perfil Code, prompts e pacotes locais na sua máquina. O ZIP genérico é o material de distribuição; o ensaio preparado contém dados e caminhos locais.
