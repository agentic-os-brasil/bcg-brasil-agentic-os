# Teste guiado do Maestro MCP

Use somente dados sintéticos. Para conferir cada cliente de forma independente e somente leitura, escolha **3 — Conferir conexão Code** ou **4 — Conferir conexão Desktop**. Para o ensaio completo de continuidade, escolha **1 — Ensaio completo no Code** e depois **2 — Retomar no Desktop**: um texto em cada cliente, com workspace e trabalho preenchidos automaticamente.

Para conferir apenas a conexão no Code, abra **Testar Maestro** e escolha **3 — Conferir conexão Code (somente leitura)**. O Code abre com o texto exato da conferência como prompt inicial, sem copiar ou colar. O perfil separado pode pedir login: conclua o fluxo normal nessa janela. A resposta deve mostrar o workspace esperado e o estado `ready`, obtidos por uma única leitura do MCP declarado pelo plugin. O estado `ready` descreve a saúde da conexão, não o estado dos trabalhos. Você pode repetir essa consulta preservando trabalhos, páginas, onboarding e memória. Se o login, o plugin ou a leitura falhar, envie a mensagem real; abrir o cliente ou ter login em outro perfil não comprova esta conexão.

No Windows, o início automático exige o executável nativo `claude.exe` no PATH. Se a mensagem indicar somente um shim, disponibilize a instalação nativa pelo fluxo autorizado ou abra **Abrir Code.cmd** sem argumentos e cole o `CODE-CONEXAO.txt` do diagnóstico atual. Para o ensaio completo, a alternativa manual usa `CODE.txt`. O kit preserva a instalação existente.

Para conferir apenas a conexão no Desktop, escolha **4 — Conferir conexão Desktop (somente leitura)**. Confirme a instalação da extensão **Maestro MCP — Ensaio …** indicada. Antes de colar, abra **Configurações → Extensões → a extensão deste ensaio** e, somente na linha **Maestro context** (`maestro_context`), selecione **✓ / Sempre permitir**. Preserve as demais permissões. ✓ / Sempre permitir libera só a leitura; gravações de conteúdo exigem revisão exata no formulário nativo ou no navegador local selecionado neste ensaio. Abra uma conversa nova e cole uma vez o texto copiado. Ele faz uma única leitura de contexto e mostra o workspace esperado e a saúde da conexão, sem consultar ou retomar trabalhos. O Desktop não exige o comando Code nem um trabalho criado no Code para essa conferência. Os pacotes já usam as pastas aprovadas; não há diretórios para copiar. Preserve outras extensões e pare se o cliente propuser substituir uma de outro ensaio.

**Revisão do dono no Desktop:** Este ensaio seleciona explicitamente a revisão local no navegador para gravações protegidas. Quando o cliente não oferece formulário nativo, uma solicitação interativa abre o registro completo no navegador deste computador. Leia o conteúdo, marque a caixa inicialmente desmarcada e escolha Aprovar alteração exata ou Recusar. Fechar a aba, cancelar ou ultrapassar 150 segundos não aprova. Formulários nativos continuam tendo prioridade quando disponíveis. Este canal local não qualifica formulários MCP, hooks ou bloqueio nativo. Se receber `confirmation_unavailable`, deixe a ação pendente e use o Code com sua confirmação nativa. Não repita a chamada, não contorne o bloqueio nem use um sim no chat como aprovação. A permissão de leitura não aprova gravações.

1. Abra **Testar Maestro** na pasta `launchers` do ensaio. O verificador testa a conexão MCP do pacote, confere os recursos e abre `RELATORIO.md`. Nenhuma chamada ao modelo é feita nessa etapa.
2. Se o relatório estiver bloqueado, envie esse Markdown ao time e pare. Preserve a pasta; o relatório distingue preparação, pacote e conexão. Se o comando `claude` estiver ausente, disponibilize o Code pelo fluxo normal antes de escolhê-lo; isso não comprova ausência do Desktop.
3. Escolha **1 — Ensaio completo no Code**. O perfil isolado abre com o texto exato do ensaio como prompt inicial, sem copiar ou colar. Faça login normalmente se solicitado. Ele verifica o ID, inicia o onboarding, descobre uma skill, propõe uma página sintética e pausa um trabalho. Confirme somente pelo fluxo apresentado pelo cliente.
4. Abra **Testar Maestro** novamente e escolha **2 — Retomar no Desktop**. Confirme a instalação da extensão **Maestro MCP — Ensaio …** indicada no relatório; ela já usa as pastas preparadas, sem campos de caminho para salvar. Preserve outras extensões Maestro e pare se o cliente propuser substituir outra extensão. Antes de colar, abra **Configurações → Extensões → a extensão deste ensaio** e, somente na linha **Maestro context** (`maestro_context`), selecione **✓ / Sempre permitir**. Preserve as demais permissões. ✓ / Sempre permitir libera só a leitura; gravações de conteúdo exigem revisão exata no formulário nativo ou no navegador local selecionado neste ensaio. Abra uma conversa nova e cole o texto já copiado: ele precisa responder pelo mesmo workspace, localizar exatamente um trabalho do ensaio e só retomar se estiver pausado. Se a extensão estiver desativada ou não aparecer, confira **Configurações → Extensões → Configurar → Ativado** nessa extensão. A chave ativada, sozinha, não confirma a conexão. Não precisa copiar IDs ou revisões.
5. Feche e reabra a conversa/conexão. Peça a leitura do mesmo trabalho e da página criada. Registre se o conteúdo persistiu. No Code, proponha uma memória sintética para aceitar e outra para recusar; verifique os resultados pelo fluxo real de confirmação.

O relatório automático mantém **Code, Desktop, login, confirmações e hooks como não testados**. A conexão feita pelo verificador não atesta que o cliente carregou o plugin. Anote o que você observou nesses clientes.

Para devolver o teste, envie somente o `RELATORIO.md` mais recente, com este complemento curto:

- Versões Code/Desktop e sistema/arquitetura.
- Code: abriu / MCP respondeu / skill funcionou / não testado.
- Desktop: importou / MCP respondeu / retomou o mesmo trabalho / não testado.
- Página e trabalho após reinício: passou / falhou / não testado.
- Memória aceita e recusada, hooks e mensagem de erro: resultado real.

Confira o Markdown antes de compartilhar. Preserve `owner`, `workspace`, perfil Code, prompts e pacotes locais na sua máquina. O ZIP genérico é o material de distribuição; o ensaio preparado contém dados e caminhos locais.
