# Maestro MCP — piloto experimental

1. Sincronize esta pasta pelo OneDrive/SharePoint e marque **Sempre manter neste dispositivo**.
2. No Mac, abra **Maestro.command**. No Windows, abra **Maestro.cmd**. Não execute como administrador. Se o sistema bloquear um programa ou script, preserve o bloqueio e peça orientação ao time; não desative as proteções.
3. A pasta Developer é criada localmente se ainda não existir. Na primeira vez, informe o diretório **já usado pelo owner do Maestro**, o workspace em Developer e o Claude Code instalado. O workspace sugerido pode ser criado pela instalação normal, depois da sua revisão. Não precisa escrever JSON, gerar IDs nem copiar arquivos para o brain. Se nunca usou Maestro, selecione a própria pasta Developer como base; a revisão normal mostrará a criação explícita de um home novo. Uma instalação existente fora de Developer precisa de orientação; este piloto não move dados. O workspace deve ser uma pasta de projeto separada do brain e da pasta do piloto.
4. Escolha o **perfil Code privado do piloto**, separado do seu perfil normal. Na criação de um perfil novo, confirme que somente nele a memória automática e os plugins sincronizados da conta ficarão desativados. Perfis existentes são preservados; configurações incompatíveis mantêm a qualificação pendente. Se necessário, o próprio programa abre o login oficial desse perfil. Nenhuma senha ou credencial é copiada. Esse mesmo perfil é usado pelo teste e pelos atalhos de gerenciar/atualizar; seu brain, owner e workspace continuam sendo os selecionados.
5. Confira as revisões exibidas antes de digitar `YES`. A preparação preserva o brain, cria somente os componentes revisados e usa o mesmo diretório compartilhado nas próximas atualizações. Mantenha a opção de cliente **complete**; se a qualificação nativa estiver bloqueada, reporte a pendência.
6. Use o menu para testar. O Code recebe o prompt automaticamente pelo executável registrado. No Desktop, a primeira instalação/ativação da extensão e a importação de skills seguem as telas normais do cliente; o menu copia **um prompt** para colar em uma conversa. Confirme a instalação pelo gerenciador. Quando a confirmação corresponde ao pacote e contrato atuais, o menu preserva sua conversa e não reabre o instalador, inclusive quando o mesmo MCPB é reutilizado após atualização. Se o pacote ou contrato mudar, a instalação volta a ficar pendente. A versão/caminho da biblioteca de skills aparece no menu; a importação no cliente continua não observada e deve ser feita se ela ainda não estiver disponível. Confirmação de instalação não comprova conexão ou funcionamento. Se aparecer outro Maestro, pare e reporte a ambiguidade.
7. Registre os resultados na opção **7** e devolva somente **RELATORIO.md**. Os JSONs e logs locais são privados. Para acompanhar uma versão nova da pasta, use **8 — Atualizar** e confira os efeitos. A atualização só aplica após sua confirmação; depois reabra o programa para conferir o resultado.

O kit é de engenharia, tem validade limitada e aceita somente as duas versões e a fonte assinada previstas na admissão. Não é uma distribuição corporativa assinada. A pasta compartilhada contém o programa; o brain e o estado privado ficam em Developer. A sincronização sozinha não ativa versões, executa tarefas ou reinstala clientes.

O diagnóstico automático verifica preparação, vínculo, pacotes atuais e leitura pelo MCP. **Ele não comprova carregamento real do Desktop/Code, identidade/skills na conversa, hooks/agentes nativos, onboarding completo, conversão de documento nem rotinas de memória.** Esses resultados dependem dos testes nos clientes e ficam separados no relatório. As respostas do menu são autodeclarações do participante.

Quando o conversor atual estiver pronto, as opções completas **1** e **2** também preparam o documento público sintético **maestro-pilot.docx** no workspace. Elas preservam um arquivo idêntico e param se já houver outro arquivo nesse nome; nada é sobrescrito. O prompt pede conversão pelo MCP atual e leitura do artefato retornado, conferindo o marcador e a tabela. Se o runtime estiver pendente, essa parte permanece pendente e o restante do ensaio pode continuar. Um runtime com identidade divergente bloqueia a jornada. **As opções de conexão/leitura e `--check-only` não preparam esse documento nem escrevem no workspace.**

Se faltar login, permissão, prova nativa ou uma parte da sincronização, a etapa fica pendente e os arquivos são preservados. Faça o login pelo fluxo normal do cliente; para sincronização incompleta, mantenha a pasta offline e execute de novo. Para divergência de owner/brain, assinatura, hash ou versão, compartilhe o relatório e peça orientação ao time; não crie outro owner para contornar o bloqueio.

Preparações anteriores sem seleção explícita de perfil permanecem preservadas e pedem revisão do time para retomar o mesmo owner. Não apague participant.json, não crie outro owner e não use seu perfil normal para contornar esse bloqueio.

Se uma sessão expirar mesmo com o login indicado como ativo, use **9 — Renovar login do perfil Code do piloto**. Ela abre novamente o fluxo oficial do mesmo perfil, com sua confirmação; o status de login sozinho não comprova uma chamada ao modelo nem a qualificação.
