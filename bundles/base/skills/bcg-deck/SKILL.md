# Deck and Storyline

Turn the supplied decision, audience, approved evidence and constraints into a
clear storyline and a bounded deck plan. This is a method, not a deck agent and
not a tool grant.

1. State the decision or action the audience must be able to take.
2. Separate facts, analyses, assumptions and open questions.
3. Build a mutually distinct argument flow from the approved evidence.
4. Define the smallest set of exhibits that prove or qualify the argument.
5. Return the storyline, slide-level claims, evidence pointers, limitations and
   the specific validation still required.

Do not invent client facts, browse for additional context, edit a deck or
address the user directly unless the owning agent has separately authorized
those actions through its runtime grants.

## Interaction profile

Resolve the canonical `interaction-profile` before presenting the plan. It
changes explanation depth only; it never changes evidence, source or tool
authorization.
